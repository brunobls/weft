# Migrating from Service Weaver to Weft

Weft is a fork of Service Weaver. The module, the root Go package and the
framework's configuration section names changed, and a few observable names
changed with them. This page lists what you have to update.

## 1. Imports and the root package

The module path is now `github.com/brunobls/weft`, and the root package is
named `weft` instead of `weaver`.

```go
// Before
import "github.com/ServiceWeaver/weaver"

type app struct {
    weaver.Implements[App]
}
func main() { weaver.Run(ctx, serve) }

// After
import "github.com/brunobls/weft"

type app struct {
    weft.Implements[App]
}
func main() { weft.Run(ctx, serve) }
```

- Rename every `weaver.X` that refers to the root package to `weft.X`
  (`Implements`, `Ref`, `Listener`, `WithConfig`, `WithRouter`, `AutoMarshal`,
  `Main`, `Run`, `InstrumentHandler`, ...). In `go.mod`, require
  `github.com/brunobls/weft` instead of `github.com/ServiceWeaver/weaver`.
- Subpackages keep their names: `weavertest`, `metrics`, `runtime/...`. Only
  their import path changes.
- The struct tag `weaver:"..."` is unchanged.
- Regenerate the `weaver_gen.go` files with the Weft generator (see
  [Installing the Weft generator](#installing-the-weft-generator)): the
  generated code refers to the new module and package. Code generated by
  Service Weaver does not compile against Weft.

## Installing the Weft generator

The `weaver generate` you already have installed is Service Weaver's: it
generates code for the old module and package. Install the Weft generator:

    go install github.com/brunobls/weft/cmd/weaver@latest

The Weft binary is also named `weaver` for now, so this overwrites the Service
Weaver `weaver` in `$GOBIN` (and installing Service Weaver again overwrites
Weft's). If you still need both, install one of them with a different
directory, for example `GOBIN=$HOME/weft-bin go install ...`, and run it by
its full path. Then run `weaver generate` in your module, as before.

## 2. Configuration files

Sections named after the old module path are **not supported**: Weft refuses
to start and the error names the section to use instead, for example

    config section "github.com/ServiceWeaver/weaver/multi" is no longer
    supported: rename it to "github.com/brunobls/weft/multi"

This also applies to the app section, to the deployer sections (`multi`,
`single`, `ssh`), to component names, and to component names listed in
`colocate`: every name that starts with `github.com/ServiceWeaver/weaver`
is an error. Weft does not read them, and it refuses to start rather than
ignore them, which would for example start an app without `mtls = true`.
Rename them by replacing the prefix `github.com/ServiceWeaver/weaver` with
`github.com/brunobls/weft`. The short section `[serviceweaver]` keeps
working.

A deployer outside this repository that builds the application's config
sections without calling `runtime.ParseConfig` does not get this error: pass
the config through `runtime.ParseConfig`.

## 3. Metrics and traces

- The `caller` label of the `serviceweaver_method_*` metrics holds the name of
  the calling component. For calls made from the application's main, its value
  changes from `github.com/ServiceWeaver/weaver/Main` to
  `github.com/brunobls/weft/Main`. Dashboards and alerts that filter on it need
  the new value.
- The framework's own control calls are traced under the root package name, so
  the span names `weaver.deployerControl.*` and `weaver.weaveletControl.*`
  become `weft.deployerControl.*` and `weft.weaveletControl.*`. Spans of your
  components are named after your own package and do not change.
- In logs, the name of the main component changes with its path: the full
  name in the `component` attribute goes from
  `github.com/ServiceWeaver/weaver/Main` to `github.com/brunobls/weft/Main`,
  and the short name that tools print goes from `weaver.Main` to `weft.Main`.
  Log filters on either value need the new one.
- Metric names, the `serviceweaver_*` prefix and the OpenTelemetry
  instrumentation library name (`.../weaver/serviceweaver`) are unchanged.
